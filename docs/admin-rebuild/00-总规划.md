# 00 - PartsPro 后台全链路重构总规划

## 目标

把现有后台从临时运营页面重构为一套稳定的 Ant Design 中后台系统。新后台直接替换旧 `/admin`，不建立 `/admin-v2` 过渡路由；所有 UI、权限、API、服务层、订单/库存/付款链路都逐步收敛到 `src/admin/` 与新 v2 数据契约。

## 范围

- UI：后台 shell、菜单、面包屑、页面头、筛选、表格、表单弹窗、确认弹窗、状态反馈。
- 权限：菜单、按钮、API mutation 三层一致校验。
- 业务：订单、客户、库存、商品、财务、员工权限、系统设置。
- 数据：标准列表响应、标准 mutation 响应、新 service/repository/schema/state-machine 分层。
- 删除：新模块验收后删除对应旧页面、旧组件、旧 lib、旧 API 调用。

## 非目标

- 不恢复 RMA 功能。
- 不清空生产数据。
- 不在第一阶段一次性删除所有旧文件。
- 不把 Vben/Vue 代码迁移进 Next.js；只吸收菜单、权限、表单、表格代理、请求规范等架构思想。

## 目录策略

```text
src/admin/
  config/          后台主题、导航、权限、模块配置
  ui/              Ant Design 后台基础组件
  services/        业务用例与 mutation 入口
  repositories/    数据读取与持久化
  schemas/         表单、查询、响应校验
  state-machines/  订单、付款、库存、客户、退款状态机
```

## 阶段顺序

### Phase 1 - 基础层

- 安装 `antd`、`@ant-design/icons`、`@ant-design/nextjs-registry`。
- 根布局接入 `AntdRegistry`。
- 后台 layout 接入 `ConfigProvider`、AntD 中文/意大利文 locale、主题主色 `#1677ff`。
- 建立 `src/admin/config` 与 `src/admin/ui`。
- 直接替换旧后台 shell，保留现有页面入口。

验收：后台可访问，桌面/移动 shell 可用，lint/typecheck/build 通过。

### Phase 2 - 权限与数据契约

- 新权限码落地：`admin:access`、`orders:*`、`customers:*`、`inventory:*`、`products:*`、`finance:*`、`staff:*`、`settings:*`、`audit:read`。
- API mutation 统一 403 与错误响应。
- 列表响应统一 `{ items, total, page, pageSize }`。
- mutation 响应统一 `{ ok: true, data }` / `{ ok: false, error }`。

验收：owner、warehouse、finance、support 四类账号菜单、按钮、API 权限一致。

### Phase 3 - 订单中心全链路

- 重写订单列表、订单详情、操作弹窗、时间线。
- 分离订单状态、付款状态、履约状态。
- 前台下单后端链路统一进入新 order service。
- 新增/替换订单与库存关键 RPC，使用 v2 命名。

验收：现金/转账/Stripe 创建订单、锁库、取消释放、付款确认、发货、自提、退款全链路通过。

### Phase 4 - 客户中心

- 统一旧 `/admin/customers` 与 `/admin/accounts/customers` 到客户中心。
- 重写客户列表、客户详情、公司资料、价格组、订单历史、备注、标签、任务、账号状态。
- 客户详情使用 Drawer/详情页组合，避免旧页面多区块堆叠。

验收：搜索、详情、价格组修改、暂停/恢复、备注/标签/任务、权限限制通过。

### Phase 5 - 库存中心

- 统一库存字段：现货、现货锁定、在途、在途锁定、可售、可预购。
- 重写库存总览、到货/缺货、流水、在途预购、手动调整。
- 所有库存变更走 service + RPC + movement + audit log。

验收：采购导入、到货、缺货、手动调整、流水、低库存预警、预购分配通过。

### Phase 6 - 后续模块

- 商品中心：SKU、编辑、新建、上下架、价格、图片、参数、多语言。
- 财务中心：付款确认、银行转账、现金、Stripe、退款、异常发票资料。
- 员工权限：员工、角色、权限矩阵、菜单/按钮权限、操作日志。
- 系统设置：商品、库存、订单、支付、通知、系统健康。

## 删除策略

旧代码只在对应新模块验收后删除。删除顺序固定为：页面引用切换、API 调用切换、旧组件引用清零、旧 lib 引用清零、旧文件删除、回归验收。

## 每阶段硬性命令

```bash
npm run lint
npm run typecheck
npm run build
```
