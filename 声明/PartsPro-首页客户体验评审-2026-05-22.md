# PartsPro 首页客户体验评审

日期：2026-05-22  
评审角色：客户视角 + 资深前端工程师  
范围：只针对首页作为购买流程入口的体验，不展开评审后台页面。  
测试路径：首页 → 商品目录/商品入口 → 加入购物车 → 购物车 → 结账页。

---

## 1. 总体结论

首页已经具备 B2B 采购平台的基础入口：搜索、目录、B2B 注册、高频 SKU、品类入口、品牌入口和服务承诺都存在。客户可以从首页进入商品目录，继续加购并到达购物车和结账页。

但从真实客户采购体验看，首页现在更像“功能导航页”，还不够像“高效采购首页”。客户在首页看到很多入口和说明，但缺少直接帮助下单的关键内容：价格状态、库存状态、MOQ、快速加购、已加购数量、复购入口、真实品类数量和可信公司信息。

---

## 2. 本次客户路径记录

### 首页

观察到的首页内容：

- 顶部发货提示：`Ordini pagati entro le 15:00...`
- 顶部 CTA：`Richiedi account B2B`
- Logo、语言切换、账户、购物车入口
- Hero：B2B 手机配件采购说明
- 主搜索入口
- `Vedi catalogo` 和 `Richiedi account B2B`
- 高频 SKU 卡片
- 服务承诺卡片
- 品类入口
- 品牌入口
- B2B 流程说明
- 页脚法律和公司信息占位

### 商品浏览与加购

从首页可以进入商品目录和商品详情。当前商品目录移动端为 2 列卡片，可以看到价格、型号、库存状态，并可加入购物车。已加入购物车的商品会显示数量。

### 购物车与结账

购物车已经变成较紧凑的采购清单，能看到 SKU、数量、单价、小计、MOQ 和结账摘要。结账页可以进入四步流程：客户、发票、配送、支付。

## 3. 逻辑方面问题

1. 首页没有根据登录状态切换重点内容  
   已登录客户仍然看到强烈的 `Richiedi account B2B` 入口。对已经登录的 B2B 客户来说，更应该显示“继续采购、常购 SKU、购物车、最近订单、RMA、专属价格组”等操作。

2. 首页高频 SKU 只能点击进入详情，不能直接采购  
   B2B 客户的典型行为是快速补货。首页的高频 SKU 卡片目前没有价格、库存、MOQ、快速加购、数量调整，不利于复购和快速下单。

3. 首页品类数量与真实商品数量不一致  
   首页显示 `320+ / 180+ / 140+ SKU`，但当前目录实际只有 6 个 SKU。即使这是未来数据占位，也会降低客户信任。上线前应改成真实统计或先隐藏数量。

4. 首页搜索没有采购级提示和结果预期  
   搜索入口存在，但缺少热门搜索、型号示例、SKU 示例、搜索建议、无结果提示说明。客户不知道搜索后会进入目录筛选还是直接定位 SKU。

5. 首页 CTA 重复且优先级不够清楚  
   顶部条、Hero、页脚都反复出现 B2B 注册。对访客有用，但对登录客户会干扰。需要按身份切换 CTA。

6. 首页链接存在未完成落点  
   品牌页、质量说明、Wholesale 等部分入口仍是占位页面。首页入口越多，越容易把客户带到未完善页面，影响信任。

7. 首页没有体现购物车状态与继续采购关系  
   顶部购物车有数量，但首页高频 SKU 和采购流程没有提示“已加入购物车 / 继续结账 / 还差 MOQ”等状态。

8. B2B 购买闭环说明不够具体  
   首页说有发票、RMA、支付、库存，但没有明确“登录后可看价格、下单后员工确认库存、支持 Stripe/PayPal/银行转账、发票字段 SDI/PEC”等完整规则。

## 4. 首页 UI 设计问题

1. 移动端顶部占用高度偏高  
   发货提示、B2B CTA、Header、搜索框堆叠后，首屏可用内容减少。采购型网站应让搜索和商品入口更早出现。

2. Hero 文案偏长  
   当前 Hero 说明较完整，但移动端阅读成本高。客户来采购时更关心“找配件、看库存、看价格、下单”，文案应更短，重点更硬。

3. 高频 SKU 卡片缺少商业信息  
   卡片显示品牌、标题、SKU、型号和状态，但没有价格、库存、MOQ、加购按钮。它更像展示卡，不像采购卡。

4. 服务承诺卡片优先级偏高  
   “Stock reale / Qualita / Spedizione / RMA”有价值，但不应挤占首屏采购入口。首页应优先：搜索、常购 SKU、品类、购物车状态。

5. 部分文案混用意大利语和英文  
   例如 `Back cover`、`Low stock`、`In stock`、`Tools` 等。意大利语默认站点应统一为意大利语，中文切换也要覆盖这些词。

6. 页脚公司信息仍是 placeholder  
   首页底部出现 `P.IVA / SDI / PEC placeholder`，这会直接影响 B2B 客户信任。上线前必须替换为真实信息或隐藏占位。

7. 首页视觉缺少真实商品感  
   当前更多是信息块和文字卡。维修配件客户需要快速确认“屏幕、电池、尾插、后盖”等真实品类。后续应加入商品图片或更接近真实配件的视觉。

## 5. 建议优先改进

### 高优先级

1. 首页按身份切换内容  
   访客：突出注册、登录、平台可信度。  
   登录客户：突出常购 SKU、购物车、继续结账、最近订单、RMA、专属价格。

2. 高频 SKU 改成可采购卡片  
   每张卡显示：库存状态、MOQ、B2B 价、VAT、快速加购、已加购数量。

3. 品类数量改成真实数据  
   Supabase 接入后从真实商品表统计。未接真实统计前，不显示夸张数量。

4. 首页搜索增强  
   增加热门搜索、SKU 示例、型号示例、搜索建议。搜索结果要明确进入商品目录并保留 query。

5. 移动端首页首屏压缩  
   减少顶部重复 CTA，Hero 文案缩短，让搜索框、目录入口、高频 SKU 更靠前。

6. 处理未完成入口  
   品牌页、质量页、Wholesale 页如果还没做完，应先跳到带筛选的商品目录，避免客户进入空页面。

### 中优先级

1. 首页增加“已加购状态”  
   高频 SKU 显示数量控件，和商品列表保持一致。

2. 增加“继续结账”浮动提示  
   当购物车已有商品时，首页显示紧凑提示：`3 pezzi nel carrello / Vai al checkout`。

3. 完善意大利语与中文翻译  
   不要混用英文状态词，中文切换要覆盖 SKU 卡片、品类、状态、按钮。

4. 将服务承诺改成更采购化的短标签  
   例如：`Stock Italia`、`IVA esclusa`、`RMA tracciabile`、`Bonifico/Stripe/PayPal`。

## 6. 尚未完善项

- 首页 SKU 数量和品类数量还不是实时数据。
- 首页高频 SKU 还不能直接加购。
- 首页没有根据客户等级显示专属价格组。
- 首页没有最近订单、重复购买、常购清单。
- 首页没有展示真实商品图片。
- 首页品牌入口和部分内容页仍需完善。
- Google 登录按钮已有，但 Supabase Google Provider 还需在后台配置。
- 法律、P.IVA、SDI、PEC、公司资料仍需正式信息。
- 下单仍是前端占位流程，最终价格和库存应由 Supabase RPC 后端计算。
- 支付入口仍是展示/占位，未接真实 Stripe、PayPal 和银行转账流程。

---

## 7. 建议下一步执行顺序

1. 先改首页身份状态：访客首页和登录客户首页分层显示。
2. 把高频 SKU 卡片升级为可加购采购卡。
3. 增加首页购物车状态条和继续结账入口。
4. 把品类数量改为真实统计或暂时隐藏。
5. 修复品牌/质量/Wholesale 的占位落点。
6. 统一意大利语和中文翻译。
7. 替换页脚公司占位信息。
